# 基本概念

图数据库用**点**表示事物，用**边**表示事物之间的关系。本文使用与快速开始相同的 `movie` 数据集：演员参演电影，用户观看电影，电影属于某个类别。

```text
演员 ──参演──→ 电影 ←──观看── 用户
                 │
               属于类别
                 ↓
                类别
```

无需先记住完整的数据结构。首次查询只用演员和电影，完整模型见[示例数据集](get-started/dataset.md)。

## 点、边和属性

**点**表示一个具体对象，例如一位演员或一部电影。**属性**描述这个对象，例如电影的 `id`（编号）和 `name`（名称）。

**边**连接两个点。例如，`Act` 边从演员指向电影，表示这位演员参演了这部电影。边也可以有属性：`Watch` 边的 `rate` 属性记录用户对电影的评分。

本数据集用 `id` 作为点的**主键**，用于区分同一类型的点。电影名称可能重复，按编号查询某部电影通常比只用名称更明确。

## 类型与标签

**类型**规定一个点或一条边的数据结构，例如 `Actor`（演员类型）和 `Movie`（电影类型）。**标签**用于匹配具有某种标记的点或边。

本数据集的演员、导演和用户分别属于 `Actor`、`Director` 和 `User` 类型，但都带有 `Person` 标签。因此：

- `@Actor` 指定演员类型。
- `:Person` 按标签匹配人物，可能同时包含演员、导演和用户。

不能把 `:Person` 理解为“只查演员”。另外，`User` 只有 `id` 属性，不具有演员类型中的 `name` 和 `birthDate`。

## 图类型与图

**图类型**规定一张图可以包含哪些点类型、边类型和属性。`movie_type` 定义了电影数据集的结构。

**图**保存实际数据。`movie` 保存具体的电影、演员及其关系。

`ngql` 的 `:play movie` 命令会自动创建这两个对象并写入内置数据，快速开始不需要您手工创建它们。

## Schema

Schema 是组织图类型和图的命名空间。可以把它理解为数据库中的目录，但它不是电脑上的文件夹。

全文默认将数据加载到 `/default_schema`：

```text
/default_schema
├── movie_type   图类型：规定电影数据的结构
└── movie        图：保存实际数据
```

加载数据前要先选择 Schema，否则数据可能进入另一个位置。具体步骤见[加载 movie 数据集](get-started/first-query.md#load)。

## 会话和选择图

连接数据库后，您在一次会话中执行 {{gql.name}} 语句。选择会话使用的图后，后续查询就知道要访问哪份数据。

!!! note "加载数据和选择图是两个步骤"

    `:play movie` 加载完成后，需要执行 `SESSION SET GRAPH movie`。重新连接后，也需要重新选择 Schema 和图，但不需要重新加载数据。完整命令见[继续上次的练习](get-started/first-query.md#resume)。
